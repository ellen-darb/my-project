# Советник диспетчера: насыщенность линии 1 Петербургского метрополитена

Хакатон «Сириус» × ГУП «Петербургский метрополитен», вектор 2. Прототип сравнивает фактический пассажиропоток с нормой для типа дня, прогнозирует его на 15–120 минут и подсказывает диспетчеру: добавить состав, снять состав или ничего не менять. Решение остаётся за диспетчером.

## Запуск демо

Откройте `web/index.html` в браузере. Сервер не нужен: данные лежат в `web/data.js`.

## Пересчёт с нуля

Нужны данные ментора (архив «Данные Сириус», xlsx с входными потоками по 15 минут) и Python 3.11+ с `pandas openpyxl numpy scikit-learn pyarrow`.

```
python3 pipeline/load.py "<папка Данные Сириус>" /tmp/entries.csv
cd pipeline
python3 run_forecast.py /tmp/entries.csv /tmp/forecast.npz     # прогноз, ~4 мин
python3 export.py /tmp/forecast.npz ../web/data.json            # бэктест и данные для интерфейса
```

## Как это работает

1. Входы турникетов по 19 станциям, шаг 15 минут, 120 дней 2026 года (февраль, май, июль, сентябрь).
2. Норма дня: медиана по дням той же группы (пн–чт, пятница, суббота, воскресенье, праздник) того же месяца.
3. Прогноз входов по станциям на 15–120 минут: градиентный бустинг поправляет норму по свежему отклонению. Каждый месяц проверяется моделью, которая его не видела.
4. Загрузка перегонов: входы по станциям превращаются в потоки по перегонам гравитационной моделью, где притяжение станций берётся по зеркальным поездкам (утренние выходы равны вечерним входам). Это допущение, а не замер.
5. Рекомендация: если прогноз выше 90% нормы 120 чел/вагон, добавить составы из резерва в пределах интервала 1:53 и 4 резервных составов. Если ниже 40% нормы, снять составы, не нарушая максимальный интервал графика и не загружая вагон выше 80% нормы. Когда интервал исчерпан, система называет станции, на которых стоит ограничить вход.

## Ограничения линии (от ментора и из файлов)

Интервал не меньше 1:53 (до 31,9 пар/ч), до 53 составов, оборот 99 минут, 8 вагонов, норма 120 чел/вагон, резерв 4 состава (по 2 в депо Автово и Северное), выход резерва 15–20 минут.

## Честные ограничения

- Абсолютное число перегрузов зависит от калибровки модели загрузки (допущения λ и масштаба потока). В `pipeline/sensitivity.py` результат проверен при пяти допущениях: при базовом перегрузов 14, при потоке +10% их 126, при −10% нет вовсе. Устойчиво другое: прогноз предсказывает 93–99% перегрузов, реактивный порог не больше 15%. Калибровка по данным метрополитена снимает вопрос.

- Загрузка вагонов не измерена, а оценена моделью. Файл с весовыми датчиками (РПДП) не удалось разобрать, поэтому калибровки по нему нет.
- В данных нет погоды и мероприятий. Календарь (праздники, пятница перед длинными выходными) учтён, погода подключается как дополнительный признак.
- Выходные не оценивались: плановая парность выходных не передана.
- День 31.08 с реальным инцидентом на Чернышевской в выгрузке потоков отсутствует (август не передан).
